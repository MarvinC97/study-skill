Next Token Prediction：Loss 怎样推动参数更新？

从“模型猜下一个 token”到概率、损失和梯度

学完你应该能做到：能够按顺序解释上下文、预测概率、目标 token、Loss 和参数更新，并说明这个演示的限制。

WHY

先建立问题意识

模型每一步会根据当前上下文，为词表中的候选 token 分配概率。训练通过目标 token 与预测概率的差距形成学习信号。

ONE TRAINING STEP · 先看链路

一次预测如何变成训练信号

上下文→候选 token 概率→目标 token→Loss→梯度与参数更新

箭头表示本例计算和训练步骤的先后／数据依赖，不代表模型只输出一个确定答案。

例子：输入“中国的首都是”。训练样本的目标 token 是“北京”。模型当前可能把概率更高地分配给别的候选，但目标仍用于计算 Loss。
MECHANISM · 逐步拆开

五个环节分别负责什么？

Context（上下文）是本次预测的输入

例如输入“中国的首都是”，模型根据这段前文计算下一个 token 的条件概率。

条件与边界：这与整段对话的 Context Window 概念相关，但这里强调的是预测发生时的前缀。

Token 是模型预测的单位

Next Token Prediction（NTP）预测的是下一个 token；token 可能是字、词的一部分或其他分词片段。

条件与边界：“预测下一个词”是便于入门的说法。

输出是概率分布

在给定上下文时，模型会为词表中的各候选 token 分配概率，所有候选概率的总和为 1。

条件与边界：示意值例如：北京 0.12，上海 0.28，其他合计 0.60。真实分词和分布由模型决定。

训练需要目标 token

训练样本给出实际接续的目标 token；例如这次示例中的目标是“北京”。

条件与边界：训练对照目标计算 Loss，不是只看模型最终选出的最高概率候选。

Loss 衡量预测与目标的差距

对于单个目标 token，交叉熵的一项可以写成 Loss = −log p(target)。目标概率越小，该项 Loss 越大。

条件与边界：这里展示单 token 的简化计算；实际训练通常跨多个 token 聚合。

参数更新改变模型的未来概率

训练通过 Loss 求梯度，再由优化器更新模型参数。理想情况下，相似上下文中目标 token 的预测概率逐步增大。

条件与边界：单次更新可能同时影响其他上下文；学习率、数据与模型结构决定实际变化。

BOUNDARIES & TRANSFER

这套机制如何连接到 Mid-training 与 SFT？

Mid-training 与 SFT 也常用 NTP

Mid-training 继续语言建模，通常对大量文档 token 计算 Loss；SFT 使用输入—理想输出示范，常对回答 token 计算 Loss。

条件与边界：Loss Masking 将不应计入损失的输入 token 屏蔽；RL 的优化信号则来自奖励目标。

Loss 下降不等于稳定能力

某个目标 token 更容易预测，是局部训练现象；模型能否稳定回答新问题，还取决于数据覆盖、上下文变化、评估分布与采样。

条件与边界：必须用独立测试与不同表述检验模型是否真正掌握相关规律。

HIDDEN QUESTIONS · 先想再点

三个小问题，把原理连接起来

点击思考 · 模型猜错时，训练系统到底知道什么？
系统有上下文、真实目标 token、模型给这个目标的概率。它用这些信息计算 Loss，再产生用于参数更新的梯度。
点击思考 · “北京”当前不是概率最高的候选，训练就完全没有方向吗？
依然有方向。目标 token 已明确，交叉熵利用它当前的预测概率提供连续的损失信号；概率越低，该样本损失越高。
点击思考 · Loss 下降一次，能证明模型真正理解中国地理吗？
不能。这说明模型在训练样本的目标预测上有所改善；是否形成可迁移知识，需要不同问法、不同上下文和留出数据的评估。
