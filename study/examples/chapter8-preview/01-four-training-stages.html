SOURCE-ANCHORED DETAILS

每个阶段具体改变什么？

Pre-training（预训练）

输入大量原始文本，训练模型根据前文预测下一个 token。它主要建立通用语言规律、世界知识和初步推理能力。

条件与边界：使用海量原始数据；训练与计算成本通常最高。

Mid-training（中期训练／继续预训练）

在已有基座上继续用目标语言、领域文档、代码或长上下文能力数据进行语言建模，补齐特定分布上的知识与基础能力。

条件与边界：通常仍采用 Next Token Prediction，并混入保留数据来缓解对旧能力的遗忘。

SFT（Supervised Fine-Tuning，监督微调）

把用户输入与理想回答组成示范对。模型学习在这类输入下怎样回答，重点塑造格式、风格、指令遵循与工作流程。

条件与边界：通常对回答 token 计算训练损失；Loss Masking 将在后续独立页面展开。

RL（Reinforcement Learning，强化学习）

模型在任务或环境里生成行为，获得奖励信号，再更新策略，增大高奖励行为出现的概率。

条件与边界：前提是奖励能可靠反映目标，且模型能够探索出有价值的行为。

改变任务缺口，训练选择怎样变化？

先判断：问题出在领域知识、输出协议，还是可验证任务的成功率？点击场景观察推荐的优先排查方向。

优先排查：领域基础 / 资料检索

知识缺口涉及大量稳定领域知识时，考虑 Mid-training；经常更新、需要引用的资料优先考虑 RAG。

这是教学决策示意。真实选择还取决于数据量、基模能力和成本。

三种条件对照（关闭脚本也可阅读）：领域知识缺失 → Mid-training / RAG；固定 JSON 输出不稳 → SFT / schema 验证；成功轨迹已存在且奖励可验证 → 评估 RL。

CONDITIONS & BOUNDARIES

为什么不能把四个阶段当成必经关卡？

四个阶段都在调整参数

在这里讨论的训练阶段中，学习信号最终用于更新模型参数。它们针对的是不同的目标分布或行为目标。

条件与边界：RAG 是检索外部资料再提供给模型的方式；通常不会因一次检索就修改模型参数。

常见顺序与跳过条件

常见路径是 Pre-training → Mid-training → SFT → RL。具体项目按已有基础能力与目标决定，部分阶段可以跳过。

条件与边界：有些基座已能可靠输出结构化格式并产生成功轨迹，可以直接开展 RL；只需要固定格式的任务可能使用 SFT 就够。

“SFT 记忆、RL 泛化”有实验条件

本章的 GeneralPoints 与 V-IRL 对照实验里，有限示范的 SFT 更易过拟合，RL 在特定分布变化上表现更好。

条件与边界：这是实验观察的概括；SFT 也能泛化，RL 也可能因奖励或环境偏差而过拟合。

数据与环境决定训练反馈质量

Mid-training 语料、SFT 示范质量、RL 环境与奖励设计决定模型接收到什么学习信号。

条件与边界：PPO、GRPO 等算法的选择属于后续学习点；算法无法自动弥补错误的训练数据和反馈。

判断顺序：先用评估定位失败原因，再决定是数据、Prompt / Harness、RAG、SFT 还是 RL。阶段选择服务于具体能力缺口。
HIDDEN QUESTIONS · 先想再点

三个小问题，把原理连接起来

点击思考 · 模型读过大量文字，为什么还可能不会按指定 JSON 回答？
预训练主要学习文本中的语言模式；SFT 可以用明确的输入—理想输出示范强化 JSON 格式与回答协议。
点击思考 · 企业知识库经常更新，应该优先把所有新事实训练进参数吗？
对需要经常更新、可追溯的事实，通常先考虑 RAG。Mid-training 更适合规模大、相对稳定且需要形成基础表征的领域知识。
点击思考 · 一个模型偶尔能完成任务，但 RL 的奖励设计很差，会自动变可靠吗？
奖励不忠实或环境不可靠时，RL 可能强化捷径或错误行为。应先检查奖励、环境和成功轨迹。
